Caveman vs Headroom: Which Tokens Actually Get Saved?

56 isolated Opus runs on real SWE-bench and SpreadsheetBench tasks, with every token classified: reasoning, answer text, tool calls, and the three input classes. The two most popular Claude Code "token savers" turn out to attack opposite sides of the ledger — and one of them broke a task.

Verdict#

On cost per solved task — the only metric that survives contact with a broken fix — stacking both tools wins at −30% vs baseline. Individually, headroom (−18%) beats caveman (−13%), because caveman's raw savings came with a casualty: it failed the hardest bugfix twice while every other condition passed it.

Take-home: on agentic work the tokens are overwhelmingly on the input side — ~460k context-replay tokens per run vs ~6k generated. Caveman compresses what the model says; headroom compresses what the model re-reads. Only the second one is where the volume lives, and only their combination cut cost without cutting quality.

The matchup#

Caveman — the output-side bet. A Claude Code plugin whose SessionStart hook injects a terse-speak ruleset from message one: drop filler, keep substance, fragments over prose, never touch code. Its lever is generation: answer text and, it turns out, reasoning. It pays rent for that lever — ~1.6k input tokens per run of skill prompt.

Headroom — the input-side bet. Not a skill at all: a local proxy on ANTHROPIC_BASE_URL that rewrites requests in flight, compressing tool outputs, logs, JSON, and replayed history before they reach the API. Zero behavioral fingerprint — the model never knows it's there. Its rent is latency: a compression hop on every request.

Because they act on different token classes, "which saves more" has no single answer — it decomposes by category and by task shape. That decomposition is the experiment.

Method#

  • Conditions ×4 — baseline · caveman (session-scoped --plugin-dir, pinned commit) · headroom (proxy v0.34.0, default settings) · both stacked. Identical model, flags, and tool surface everywhere.
  • Tasks ×7, from real benchmarks — three SWE-bench Verified instances (pylint, pytest, sphinx) gated by the official held-out test patches; one contributor-doc writing task on the pylint checkout; three SpreadsheetBench instances (one with 2.7 MB workbooks) gated by cell-level checkers. Quality gates run outside the agent.
  • Isolation — every run in a fresh throwaway workspace: --setting-sources "" (no user config, hooks, or plugins), no CLAUDE.md, no memory, no session persistence, pinned tools, scrubbed env. The condition is the only variable.
  • Measurement — full stream-json event capture. Input classes and totals are exact API usage; the output split (reasoning / answer text / tool calls) is derived — visible chars anchored to exact per-message totals, reasoning as the residual, so hidden thinking still counts.
  • Scale — 2 trials per cell: 4 × 7 × 2 = 56 runs on claude-opus-4-8, 2h16m wall, zero errors. Deltas under ~15% treated as noise.

Where the tokens go#

Mean output per run, split by category. Caveman's cuts land exactly where its pitch says — answer text −47% — plus one it doesn't advertise: reasoning −42%, because terser trajectories are shorter everywhere. Headroom leaves output untouched.

The quality catch#

Across 56 runs, the only quality divergence was caveman alone failing the sphinx bugfix — both trials — with incomplete fixes (the dedent + append/prepend combination case), while baseline, headroom, and even the caveman-containing stack went 2/2. One task at N=2 is a pattern, not a proof. But it is exactly the failure mode a raw −30% cost number hides, and it is why cost-per-solved is the headline metric here: on it, caveman drops from first place to third.

Directionally it makes sense: a ruleset that compresses the model's working narration also compresses the thinking that narration carries (reasoning −42%). Most of the time that's free. On the subtlest task in the battery, it wasn't.

Caveats#

  • N=2 per cell. Big deltas (−45% cache-read, −47% answer text) are robust; single-cell effects (C3) are a flag to investigate, not a conviction.
  • One model (claude-opus-4-8), one battery shape. Caveman's ceiling rises on chat-heavy workloads; headroom's rises with bulkier tool outputs.
  • O1/O3 failed for all conditions identically — SpreadsheetBench's ground truth wants blank cells via IFERROR(…,"") where agents write #N/A or computed values. Equal-opportunity misses; comparisons unaffected.
  • SWE-bench environments are recreated natively (no Docker) with the official held-out test patches applied at gate time — fine for token measurement; don't quote the pass rates as official SWE-bench scores.
  • Output split is derived (chars anchored to exact totals, reasoning as residual); input classes and all totals are exact API usage.
  • Methodological disclosure: two harness bugs were caught by built-in cross-checks during analysis — stream events arrive per content block (output totals must come from the result event), and a test-tampering check that false-flagged every pytest-repo source file (src/_pytest/…). Both fixed; C2 re-gated from 0/8 to 8/8.

Reproduce#

The harness is a small stdlib-Python repo; conditions are a few declarative lines each, so adding a new "token saver" to the gym is a one-file change.

python3 fetch_tasks.py            # pin benchmark instances
python3 gym.py smoke              # auth + activation checks
python3 gym.py run --phase full   # 4 conditions × 7 tasks × 2 trials
python3 analyze.py full           # summary + results.json

isolation per run: fresh workspace · --setting-sources "" · pinned tools · scrubbed env · session-scoped plugin/proxy injection · no session persistence
